# 2.0 — Catálogo Global de Produtos

## Decisão
O Lista de Compras Inteligente 2.0 terá um **catálogo global compartilhado**, para evitar que cada casa tenha que cadastrar manualmente o mesmo produto.

## Estrutura
- Cada produto terá um `product_id` interno próprio.
- EAN/GTIN será um identificador forte quando existir, mas não será o único identificador.
- Organização conceitual: **Família → Variante → SKU/Embalagem**.
- Exemplo: `Arroz Cristal → Tipo 1 → Pacote 5 kg`.
- Embalagens/tamanhos diferentes são SKUs diferentes, mesmo pertencendo à mesma família.

## Origem dos dados
- Começamos consumindo APIs externas confiáveis para descobrir e enriquecer produtos.
- Os produtos normalizados são gravados no nosso banco.
- Nosso banco será a fonte principal usada pelo app; não queremos depender de consultar APIs a todo momento.
- Futuramente NFC-e/notas fiscais poderão enriquecer e validar o catálogo.

## Busca e desempenho
A busca não carregará todas as informações do produto de uma vez.

### Camada leve para busca
- ID
- EAN/GTIN
- nome
- marca
- categoria
- variante
- quantidade/peso
- unidade
- imagem pequena, quando confiável

### Detalhes sob demanda
Composição, ingredientes, nutrição, fabricante, descrições, imagens maiores e demais metadados serão carregados apenas quando necessários.

A busca será progressiva e indexada, evitando consultar dezenas de campos e variações para cada resultado.

## Ranking da busca
Ao pesquisar, a prioridade será:
1. produtos que aquela casa compra normalmente, considerando frequência e recência;
2. produtos populares na região;
3. restante relevante do catálogo global.

## Formas de encontrar produtos
Prioridade inicial:
- digitação/pesquisa por nome;
- navegação por categorias;
- produtos identificados posteriormente por nota fiscal.

Scanner de código de barras fica preparado arquiteturalmente, mas não é prioridade inicial do 2.0.

## Experiência do usuário
A interface será simples por padrão. Exemplo:

`Arroz Cristal Tipo 1 — 5 kg`

Estruturas técnicas, composição e outros detalhes ficam escondidos até o usuário pedir.

Usuários que desejarem entender diferenças poderão usar detalhes do produto e, futuramente, conversar com a IA.

## Papel da IA
- explicar informações existentes no catálogo;
- ajudar a comparar variantes;
- investigar correspondências quando os dados forem incompletos;
- auxiliar na normalização.

A IA **não é dona do conhecimento do produto** e não deve inventar identidade, composição ou imagem. O catálogo/banco é a fonte de conhecimento.

## Produtos semelhantes e duplicidades
Nome parecido sozinho não define igualdade.

O sistema deverá considerar sinais como:
- EAN/GTIN;
- marca;
- variante/tipo;
- embalagem/peso;
- unidade;
- descrição/composição quando disponível.

Correspondência de alta confiança pode ser resolvida automaticamente. Casos ambíguos vão para validação administrativa.

## Criação de produtos
- **Usuário:** não cria diretamente no catálogo global; ele sugere.
- **Sistema:** pesquisa, compara, normaliza e pode validar automaticamente quando houver evidência segura.
- **Admin:** cria produtos e resolve casos duvidosos/exceções.

Enquanto uma sugestão aguarda validação, o usuário poderá continuar usando um item provisório privado da casa, sem travar sua lista.

## Imagens
Imagens devem vir de origem confiável, como catálogo/API confiável, fabricante ou correspondência segura por EAN/GTIN. A IA não deve escolher uma imagem apenas porque visualmente ou textualmente parece corresponder ao produto.

## Princípio final
**Banco próprio como núcleo; APIs como fontes auxiliares; dados leves para busca; detalhes sob demanda; experiência simples para o usuário e validação técnica fora da sua rotina.**
