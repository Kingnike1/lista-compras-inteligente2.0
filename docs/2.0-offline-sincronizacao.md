# 2.0 — Offline e Sincronização

## Objetivo
Manter o comportamento do aplicativo previsível e seguro quando não houver conexão, evitando conflitos complexos de sincronização e alterações divergentes entre membros da mesma casa.

## Regra principal
**Sem conexão com o servidor, o aplicativo opera em modo somente leitura.**

O modo offline existe para consulta, não para alteração de dados.

## O que pode funcionar offline
Quando houver dados locais previamente armazenados, o usuário pode consultar informações como:
- estoque;
- lista de compras;
- histórico disponível localmente;
- outros dados já carregados no dispositivo.

Esses dados representam o último estado conhecido pelo aparelho e podem estar desatualizados.

## O que não pode funcionar offline
Sem conexão, não devem ser permitidas operações que alterem o estado persistente, incluindo:
- adicionar, remover ou editar itens;
- alterar estoque;
- marcar ou desmarcar itens quando isso persistir estado;
- concluir compras;
- registrar preços;
- modificar orçamento;
- alterar configurações da casa;
- executar outras escritas que dependam de persistência no servidor.

## Experiência do usuário
A interface não deve simplesmente falhar ou deixar botões sem resposta.

Quando o usuário tentar realizar uma alteração offline, deve receber uma mensagem clara, por exemplo:

> Você está offline. Conecte-se à internet para fazer alterações.

A interface deve indicar de maneira simples quando os dados exibidos são o último estado armazenado localmente.

## Retorno da conexão
Quando a conexão retornar:
1. o aplicativo consulta o servidor;
2. recebe o estado atual autorizado;
3. atualiza o cache/local state;
4. libera novamente as operações de escrita.

O servidor continua sendo a referência para o estado persistente.

## Conflitos de sincronização
O 2.0 não implementará edição offline com fila de mutações.

Consequentemente, não será necessário reconciliar posteriormente alterações concorrentes feitas offline por dois membros da mesma casa.

Isso reduz complexidade, risco de perda de dados e estados difíceis de explicar ao usuário.

## Recursos naturalmente online
Recursos como comparação de mercados, preços recentes, descoberta de mercados, IA e informações dependentes de APIs podem exigir conexão.

Quando fizer sentido e houver cache válido, o aplicativo pode mostrar o último resultado conhecido, deixando claro que não representa necessariamente informação atual.

## Evolução
Uma arquitetura de escrita offline poderá ser estudada futuramente se houver necessidade real comprovada. Ela não faz parte da arquitetura inicial do 2.0.

## Princípio final
**Offline serve para consultar o último estado disponível. Online é obrigatório para modificar dados. O 2.0 prioriza consistência e simplicidade em vez de sincronização offline complexa.**
