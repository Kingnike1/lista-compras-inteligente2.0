# 2.0 — Promoções e Histórico

## Objetivo
Separar claramente fatos observados pelo sistema de promoções declaradas pelos mercados, evitando anunciar ofertas sem uma fonte confiável.

## Regra principal
**Promoção não é uma funcionalidade central enquanto não existirem fontes confiáveis, atuais e verificáveis.**

O sistema não deve deduzir que algo está em promoção apenas porque o preço caiu.

## Preço normal × promoção
Preço normal e promoção são entidades/conceitos diferentes.

Uma promoção, quando disponível, pode possuir:
- produto/SKU;
- filial ou rede aplicável;
- preço promocional;
- período de validade;
- condições da oferta;
- fonte/proveniência;
- data de verificação;
- estado de confiança.

A promoção nunca deve sobrescrever o histórico do preço normal.

## Fontes aceitas
Uma promoção só pode ser apresentada como promoção quando houver uma fonte concreta e suficientemente confiável, como:
- API oficial ou parceiro autorizado;
- integração direta com mercado/rede;
- encarte digital confiável e identificável;
- fonte oficial do estabelecimento;
- outro provedor validado pelo sistema.

Sem fonte confiável, **não mostramos uma promoção**.

## Histórico de preços
O histórico continua sendo uma funcionalidade importante independentemente da existência de promoções.

Cada preço observado mantém:
- SKU;
- filial;
- valor e moeda;
- data/hora;
- fonte;
- estado de validação/confiança.

Registros históricos não são apagados quando surge um preço novo.

## Preço historicamente baixo
Com histórico suficiente, o sistema poderá informar que um preço atual está abaixo do comportamento histórico observado.

Exemplo conceitual:
> Este preço está abaixo da média recente observada.

Isso é uma **análise do próprio sistema**, e não uma afirmação de que o mercado criou uma promoção.

Portanto:

**promoção declarada pelo mercado ≠ preço historicamente baixo calculado pelo sistema.**

A interface deve deixar essa diferença clara.

## Comparador
O Comparador 2.0 não depende da existência de promoções.

Quando uma promoção confiável existir, ela poderá ser considerada conforme suas condições e validade. Quando não existir, o comparador continua normalmente com os preços válidos disponíveis.

Promoções vencidas ou sem confirmação atual não devem ser tratadas como vigentes.

## Confiança e Admin
Promoções seguem o Sistema de Confiança 2.0.

Dados conflitantes, incompletos ou de origem duvidosa podem exigir revisão do Admin antes da publicação.

O Admin deve conseguir verificar fonte, validade e divergências quando houver exceção.

## Evolução
A arquitetura fica preparada para promoções desde o 2.0, mas a funcionalidade ganha destaque apenas quando a plataforma possuir cobertura de dados suficiente e fontes confiáveis.

Isso permite adicionar futuramente parceiros, APIs e integrações de redes sem reconstruir o domínio de preços.

## Princípio final
**O aplicativo nunca inventa uma promoção. Se existe fonte confiável, podemos mostrá-la. Se não existe, usamos apenas fatos de preço observados e, quando houver histórico suficiente, análises próprias claramente identificadas como análises — não como ofertas do mercado.**
